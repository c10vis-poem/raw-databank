## The tool — `tools/check.py`

Built to satisfy hard rule 5, so it shares no code and no method with
`tools/clean.py` and does not import it.

| | `tools/clean.py` | `tools/check.py` |
|---|---|---|
| pdf | pymupdf `page.get_text()` | **pypdf** `PdfReader.extract_text()` |
| docx | pandoc `docx -> markdown` | **stdlib** `zipfile` + `xml.etree` over `word/document.xml`, headers, footers, foot/endnotes, and `document.xml.rels` hyperlink targets |
| html | pandoc `html -> plain` | **stdlib** `html.parser`, one text node at a time, tag boundaries kept |
| text | `open().read()` | byte read + BOM/encoding probe |
| zip | skipped | opened and enumerated |
| compare | `Counter` word-frequency multiset difference | containment of named atoms and order-sensitive segments in a fold-and-squash character stream, greedy chunk splitting to name the culprit, plus an exact `difflib` line audit where extraction is byte-faithful |

No word frequencies anywhere in it. No percentage is ever printed. Every
finding carries the verbatim text it is about.

The load-bearing trick is **squash**: fold to ASCII, lowercase, delete every
non-alphanumeric character. `CHIP SM8750` and `CHIPSM8750` both become
`chipsm8750`, so a value welded to its neighbour is still findable — and
comparing that against a boundary-preserving stream says whether the boundary
survived. That is what makes the fused-token blind spot visible.

    python3 tools/check.py            # write 03-check/
    python3 tools/check.py --dry-run  # roll-up only, writes nothing

Rerun it whenever `01-sources/` or `02-clean/` changes. It rewrites the tree.

1. **Fused tokens** — caught. See above. `nova-corpus-device-stack.md` is the

2. **Mid-sentence truncation** — caught, and it is worse than three files.
   **26 sources end mid-sentence in the source itself.** All three that were

## Calibrating the checker — what was thrown out, and why

Three rounds of findings were discarded as the checker's own fault, not
`clean.py`'s. Recording them so nobody re-adds them:

- **pypdf welds tightly-set figure cells.** In the Continual Harness paper it
  reads a heatmap row as `0.400.95`, where pymupdf correctly gives
  `0.40 0.95`. Demanding that `0.400` appear as a standalone token in the
  cleaned file invents a failure. The checker now refuses to assert about any
  atom that its *own* extractor did not produce as a complete run, and counts
  those set-aside atoms in each report.
- **Consecutive `w:hyperlink` elements in one docx paragraph have no separator**
  of their own, so the first pass welded a dozen URLs into one string. Fixed in
  the extractor.
- **A contiguous-tail test is too brittle.** pypdf and pymupdf disagree about
  icon-font glyphs at the end of a page (`arrow_circle_down copy`), which is
  not a truncation. The edge test is chunk-based now.

The general lesson: an independent checker will disagree with the cleaner for
reasons that are the checker's fault, and every one of those has to be run down
by hand before it is reported. The first run produced 67 fails; 8 survived.

## Environment note

This session ran in a remote container, not on the device. **Neither pymupdf
nor pandoc was available there** — which is why `check.py` uses `pypdf` and the
standard library. That is hard rule 7 working as intended, and it made the
independence stronger than it would otherwise have been: nothing was shared
with `clean.py` because nothing *could* be.

`pypdf` needed `pip install cffi` first — the system `cryptography` was broken
and `pypdf` imports it eagerly.

## Working rules — unchanged, plus one

Everything in the 2026-08-26 handoff still stands. One addition:

- **A checker's disagreement with the cleaner is a hypothesis, not a finding.**
  Verify each one by hand against both files before writing it down. Reporting
  an artifact of your own extractor as a content loss is worse than not
  checking at all, because it looks like evidence.
